# 艾尔登法环 · 攻略站

基于 **Vue 3 + Element Plus + Vite** 的《艾尔登法环》中文攻略站，覆盖主线、支线、区域、BOSS 攻略、武器、护符、魔法、祷告、骨灰九个内容模块，外加追忆兑换、构筑器、进度总览三个工具页，全部为数据驱动，无后端。

## 功能

### 主线

- 章节时间线，标注进入条件、目标等级、武器强化档位、推荐追忆；本体与 DLC 各自成链，不会从灰烬王城直接跳到幽影之地
- 章节详情：分步流程、BOSS 清单（区分必打）、关键道具、易错过警告（可直接跳转到对应支线）、下一步条件
- 结局对照：6 个结局的触发条件与前置支线
- 本地进度：`localStorage` 记录已通关章节

### 支线

- 51 条支线全部含分步流程，每步带地点、细节与提示，另附前置条件、奖励、分支对照
- 关键词搜索覆盖 NPC / 区域 / 奖励 / 步骤正文；支持区域筛选、本体/DLC 切换、仅看易错过、按完成状态过滤
- 详情页：步骤时间轴、分支后果、关联支线（真实 id 互链，构建期校验）、同区域支线、上下条翻页
- 本地进度：`localStorage` 记录已完成支线，列表页显示「我的进度」

### 区域 & BOSS 图鉴

- 按地表 / 据点 / 地下 / 幽影之地四层分组，区域卡片含进入方式、子区域、章节归属与关键道具
- BOSS 可单独搜索，标记是否追忆、是否必打；追忆总表单列 25 个追忆 BOSS
- BOSS 若关联支线，名字后直接给出跳转链接

### BOSS 攻略

- 105 个 BOSS 逐个给出推荐等级、武器强化档位、弱点 / 抗性 / 免疫、打法要点、可召唤帮手与掉落
- 数据分三层：`regions.js` 记「有哪些 BOSS、在哪」，`bossGuides*.js` 记「怎么打」，`remembrances.js` 记「追忆能换什么」，同一个事实只存一份
- 同源 BOSS 用「家族继承」（25 个家族）：树人、黑夜骑兵、死鸟这类换皮 BOSS 共用弱点与打法，个别 BOSS 只写差异，避免抄 105 遍
- 详情页地址是 `/bosses/:region/:name` 两段路径 —— 「死鸟」「黑夜骑兵」在不同区域各有一只，单用名字无法唯一定位
- 列表页支持关键词、区域、本体/DLC、必打/追忆、BOSS 类型、弱点六维筛选与四种排序，状态写入 URL
- 属性弱点没有把握的一律留空并显示「无特别弱点记录」：写错属性会让玩家把武器附错属性，比不写更糟

### 武器

- 数值、补正、需求、战技、异常状态、获取位置与玩法要点全覆盖
- 筛选：关键词（名称 / 战技 / 玩法 / 异常状态）、42 个类型分组多选、补正属性、异常状态、版本（全部 / 本体 / DLC）、只看收藏
- 排序：名称、物理面板、补正总和、重量；卡片与表格双视图
- 详情页：攻击力条形图、补正与需求对照、战技说明、推荐配装、同类型面板最接近的武器、上下件翻页

### 护符 / 魔法 / 祷告 / 骨灰

四个模块共用一套通用图鉴组件（`views/CodexView.vue` + `views/CodexDetailView.vue`），由 `src/data/codex.js` 注册表注入配置：

- 统一的分类筛选、推荐度（S/A/B/C）、只看核心 / 只看 DLC、按 FP / 记忆格 / 重量排序
- 详情页含效果、获取位置、分类思路、同类推荐与上下文跳转
- 每个模块在注册表里附带「分类思路」文案，解释各分类之间的取舍

### 追忆兑换

- 25 个追忆 BOSS 逐个列出「这个追忆能换什么」，本体 15 + DLC 10
- 每件兑换物带类型标签（武器 / 魔法 / 祷告 / 护符 / 战灰 / 道具）；已收录进图鉴的直接可点开详情（46/51）
- 标明直接使用可得卢恩数；约定之王拉塔恩单独标注「唯一可三选一」
- 支持按 BOSS 名 / 兑换物名搜索，以及本体 / DLC、兑换物类型筛选
- 从区域图鉴的追忆 BOSS 可一键跳到对应条目（`?q=BOSS 名`）

### 构筑器

- 选主手 / 副手武器 + 四个护符 + 记忆格法术，实时算出总负重、负重档位、属性需求缺口与 FP 消耗
- 负重按官方分段公式计算：耐力 20 → 64.1，99 → 160，负重类护符（众武护符系、黄金树的恩惠系）之间按乘法叠加
- 负重档位按「占最大负重百分比」判定：`<30%` 轻 / `30–69.9%` 中 / `70–99.9%` 重 / `≥100%` 超重，进度条上标了 30% 与 70% 两条刻度
- 给出「想进上一档需要多少耐力」：从 1 级往上逐级试到 99，和游戏里加耐力看负重条的行为一致，比反解分段函数更好核对
- 需求检查区分主手与副手：双手持握只对主手生效，力气按 1.5 倍（向下取整）计算；弓弩、盾牌、法杖、圣印记不支持双手持握，界面不显示该开关
- 负重护符不写死对照表，而是解析护符 `effect` 文案里的「装备重量上限 +19%」「负重 +5%」，以后补护符不用改代码
- 四套预设（月光剑法系 / 力敏出血 / 信仰战士 / 重装大盾），一键填入并附注意事项
- 整套构筑写入 URL query，可刷新、可分享、可后退；链接里出现失效 id 会自动清洗，不会凭空多出或少一件装备

### 我的进度

- 主线章节、支线任务、武器收藏、图鉴收藏四项汇总在一页，各自带完成度进度条
- 支线部分额外按区域分布统计，并分别列出已完成 / 未完成清单
- 导出 / 导入 JSON：换设备或清缓存前可先存一份；导入是覆盖式的
- 四项进度统一由 `composables/progress.js` 管理（`createIdStore` 保证同一个 key 只创建一份响应式状态），旧的三个 composable 变成薄封装，对外 API 不变

### 跨模块与全站检索

- 武器详情页「推荐配装」里的护符、魔法、祷告、武器搭配全部可点，直达各自图鉴条目；匹配不到的描述性标签（如「副手盾牌或第二把同系武器」）保持纯文本
- 全站搜索（`Ctrl/⌘ + K`）一次输入同时查武器、护符、魔法、祷告、骨灰、支线、主线章节、区域、BOSS、追忆兑换、工具页，共 1154 条索引
- 搜索索引按需加载（首次打开才 import），不进入首屏 chunk
- 武器 / 图鉴 / 区域 / 追忆 / BOSS 页的筛选与分页状态写入 URL query，刷新不丢、链接可分享、浏览器后退可回到上一个筛选组合

## 开发

```bash
npm install
npm run dev      # 开发服务器（predev 会自动生成统计与 404.html）
npm run build    # 产物输出到 dist/
npm run preview  # 预览构建产物
npm run check    # 页面回归检查（172 项）
```

`npm run check` 按模块分成八组断言：

1. `usePagination` 的纯逻辑（页码折叠、越界钳制、筛选重置、结果变少收敛）
2. 武器列表的 SSR 实渲染（首屏卡片数、页码、骨架）
3. 四个图鉴模块分页后不再出现「每批 48 条」的漏项
4. 404 兜底：catch-all 路由与 `public/404.html`
5. 追忆兑换表（25 追忆 / 51 物品 / 46 条可链接）、跨模块链接、全站搜索索引
6. BOSS 攻略：105 个 BOSS 的完整性、同名 BOSS 按区域区分、详情页空态
7. 进度存储层：key 隔离、导出 / 导入 / 清空、图鉴收藏跨模块不串味
8. 构筑器：负重公式逐点核对、档位边界、需求检查与双手持握、URL 往返与失效 id 清洗

## 部署到 GitHub Pages

仓库已配置 `.github/workflows/deploy.yml`，push 到 `main` 即自动构建并发布。

本地手动构建子路径产物：

```bash
# Git Bash 需要 MSYS_NO_PATHCONV=1，否则 /static-site-demo/ 会被当成路径转换
MSYS_NO_PATHCONV=1 BASE_PATH=/static-site-demo/ npm run build
```

`vite.config.js` 读取 `BASE_PATH` 作为 `base`，路由使用 `import.meta.env.BASE_URL`。

### 深链接如何处理

这是 history 路由部署到静态托管的经典问题：直接访问 `/weapons/moonveil` 时服务器上没有对应文件，会返回 404。

处理方式分两层：

1. `scripts/gen-404.mjs` 在 `predev` / `prebuild` 阶段生成 `public/404.html`，把部署 `base` 写进脚本。404.html 先把真实路径存进 `sessionStorage`，再跳回站点根。
2. `src/router/index.js` 在创建 router 之前读回 `sessionStorage`，用 `history.replaceState` 把地址改回目标路径，用户感知不到中间跳转。

`public/404.html` 因此不入库（已加入 `.gitignore`），因为它依赖构建期的 `BASE_PATH`。

站内还有一个 catch-all 路由指向 `NotFoundView`，访问不存在的路径不会白屏。

## 架构

```
数据文件（src/data）→ utils 计算 / 筛选 → 视图渲染
                          ↑
              summary.js（构建期生成，首页专用）
```

几个约定：

1. **数据与视图分离**：每个模块的筛选、排序、匹配逻辑放在 `src/utils/*.js`，视图只负责渲染与交互；同类模块共用一个视图，差异通过注册表注入。
2. **首页统计独立**：`scripts/gen-summary.mjs` 在构建期从数据文件生成 `src/data/summary.js`，首页只读这几个数字，不引入完整数据集。
3. **列表分页**：`src/composables/usePagination.js` 接收「已筛选排序完成的完整列表」，输出分页切片。默认 20 条/页，另有 48 / 120 / 全部三档。
   - 之所以保留「全部」：分页后未展示的条目不在 DOM 里，浏览器 Ctrl+F 搜不到，容易被误认为数据缺失。结果条会提示当前处于哪种模式。
   - 筛选 / 排序任一变化都回到第 1 页（`resetToken` 指纹），结果变少时收敛越界页码。
4. **进度与收藏**：`useQuestProgress` / `useMainProgress` / `useWeaponFavorites` / `useCodexFavorites` 共用 `composables/progress.js` 里的 `createIdStore`，各占一个 `localStorage` key，互不干扰；同一个 key 只会创建一份 ref，天然跨组件共享。
5. **同一事实只存一份**：区域图鉴记「有哪些 BOSS」，BOSS 攻略记「怎么打」，追忆表记「能换什么」，三处靠 `${regionId}::${bossName}` 复合键与家族名对上，不复制内容。
6. **长列表不铺 DOM**：构筑器的武器 / 护符 / 法术选择器用 480 条数据也只渲染前 24 条匹配结果（`components/ItemPicker.vue`），不用 `el-select` 全量铺开。

## 目录结构

```
scripts/
```

## 数据说明

- 武器面板为游戏内**未强化基础值**；盾牌不计攻击力。热门武器数值准确，冷门武器为同类型基准估算。
- 获取位置只精确到区域或主要地标，不臆造具体房间。
- 译名以简中官方为准，部分条目在数据文件里保留别名以便搜索。
- 内容整理自公开攻略资料与社区 Wiki，仅供学习交流，与 FromSoftware / 万代南梦宫无关。
